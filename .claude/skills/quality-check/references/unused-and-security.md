# 観点4: 未使用コード・基本的なセキュリティ観点

## 未使用(orphan)コードの検出

### フロントエンドコンポーネント

`frontend/src/components/`配下の各`.tsx`ファイルについて、ファイル名(コンポーネント名)を`Grep`で検索し、自分自身の定義以外にimportしている箇所があるか確認する。

```
Grep pattern="ComponentName" path=frontend/src glob=**/*.tsx
```

importしている箇所が定義ファイル自身しかない場合、そのコンポーネントはUIツリーに組み込まれていない(orphan)。

### バックエンドのエンドポイント・DTO

`*Controller.java`の各エンドポイントについて、対応するDTO(例: `CardBulkUpdateRequest`)が`frontend/src/api/`配下から実際に呼ばれているか確認する。

```
Grep pattern="/api/cards/bulk" path=frontend/src
```

フロントエンドのAPI関数(`frontend/src/api/*.ts`)が定義されているだけでコンポーネントから呼ばれていない場合も同様にorphanとして扱う。

### 判定後の扱い

orphanなコードが見つかった場合、それ自体を「バグ」として断定せず、以下のいずれかである可能性を報告に併記する。
- 実装途中で放置された未完成機能(docs-consistency.mdの「ドキュメント優先」パターンと合わせて判断)
- 将来のために先行実装されたが、まだUIに配線されていないもの

対応(UIに組み込む/削除する)はユーザーの判断を待つ。

## 基本的なセキュリティ観点

個人利用アプリ(ローカル、およびAWS上では許可した自分のIPからのみアクセスできる構成)という前提(`docs/features.md`の非機能要件「セキュリティ」参照)を踏まえ、過剰な指摘をしないよう注意する。以下は最低限確認する。インフラ(`infra/`)側のセキュリティは`references/terraform-infra.md`で確認する。

- **入力バリデーション**: 全ての`@RequestBody`を受け取るエンドポイントで、対応するDTOに`@Valid`が付与され、必須項目に`@NotBlank`/`@NotEmpty`等が設定されているか。
- **例外情報の漏洩**: `GlobalExceptionHandler`の`handleUnexpected`のように、想定外の例外はスタックトレースをレスポンスに含めず、ログにのみ出力しているか。新しいエンドポイントを追加した際にこの共通処理を経由しているか(個別に`try-catch`でスタックトレースを`toString()`してレスポンスに含めていないか)。
- **SQLインジェクション**: `@Query`のJPQLで文字列連結による動的クエリを組み立てておらず、`:paramName`によるバインドパラメータを使っているか(`ColumnRepository`/`CardRepository`のパターン参照)。
- **CORS設定**: `WebConfig.java`のCORS許可オリジンが、意図せず広すぎる設定(全オリジン許可等)になっていないか。ローカル開発用の設定であることが明確か。
- **機密情報のハードコード**: パスワード・APIキー等が設定ファイルやソースコードに平文で書かれていないか(本プロジェクトは個人ローカル用のため`application.properties`のDB認証情報程度は許容範囲だが、外部サービスの認証情報等が紛れ込んでいないかは確認する)。

## 報告時の注意

このプロジェクトは学習目的の個人利用アプリであり、認証機能や不特定多数への公開を想定していない(`docs/features.md`参照)。エンタープライズ向けの厳格なセキュリティ要件(認可制御、監査ログ等)を求める指摘は本プロジェクトのスコープ外として扱い、報告しない。
