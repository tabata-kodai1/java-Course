# 🌐 Webアプリケーション開発 ITリテラシー理解度チェック

タスク管理アプリ「TaskManagement」の開発を通じて身につけるべき、Web技術の基礎理解度チェックの回答。

## 第1章 インターネットとネットワークの仕組み(12問)

### Q1. インターネットとは

「インターネット」と「Webブラウザで見るホームページ」は同じものですか?違うとすれば、どう違いますか?

インターネットはコンピューター同士が通信するためのインフラで、Webページはそのインターネットを利用して提供され、HTMLなどで記述されているもの。

### Q2. IPアドレスとポート番号

このプロジェクトではフロントエンドを `localhost:5173`、バックエンドを `localhost:8080` で起動しています。

- `localhost`とは何を指しますか?
- `:5173` や `:8080` のようなポート番号はなぜ必要ですか?

`localhost`=自分のPCのことを指します。ポート番号は、自分のPCの中でいろいろと動いている際に、どの場所に届けたいかを区別するための番号。

### Q3. DNS

ブラウザのアドレスバーに `https://www.example.com` と入力してからページが表示されるまでに、DNSはどのような役割を果たしますか?

名前と通信に使うIPアドレスを結びつける電話帳のような役割。

### Q4. HTTPとは

HTTPとは何の略で、どのような役割を持つものですか?「プロトコル」という言葉の意味も含めて説明してください。

HyperText Transfer Protocolであり、Webブラウザーとwebサーバーの間で通信するためのルール。

### Q5. HTTPとHTTPSの違い

HTTPとHTTPSの違いは何ですか?なぜ現在のWebサイトはほぼすべてHTTPSを使用していますか?

HTTPはWebブラウザとWebサーバーが通信するためのルールで、HTTPSはそのHTTP通信を暗号化などによって安全にする仕組み。通信途中で第三者に内容を盗み見られたり、改ざんされたりするリスクなど、情報漏洩など機密なものを保護するため。

### Q6. リクエストとレスポンス

Webにおける「リクエスト」と「レスポンス」の関係を、日常生活の例えを使って説明してください。

レストランで例えると、リクエストはお客様が頼む注文、レスポンスは頼まれた注文の料理を運んでくること。

### Q7. HTTPメソッド

このアプリのAPIでは以下を使っています。

- GET 商品ページ
- POST かごに入れ注文する
- PUT 注文したもの入れ替える
- DELETE 注文をキャンセルする
- PATCH 買った商品の一部を変更する

これらの「HTTPメソッド」とは何ですか?日常生活の例えで、それぞれの違いを説明してください。

ブラウザーがサーバーに対して何をしたいかを伝える言葉。

### Q8. HTTPステータスコード

サーバーからの返事には「ステータスコード」という3桁の数字が含まれます。以下のコードはそれぞれ何を意味しますか?

- 200 サーバーがリクエストを受け取って、正常に処理できたこと

- 201 サーバーが正常に処理ができたことと、新しい情報の登録ができたこと
- 400 リクエストの内容不備、不正で処理できない
- 404 リクエストしたが、探しているものが見つからない
- 500 サーバー側で予期しないエラーがあり、正常に処理ができなかった

### Q9. JSONとは

フロントエンドとバックエンド間でデータをやり取りする際に「JSON」という形式が使われています。

- JSONとは何ですか?
- なぜ広く使われていますか?

データをやり取りするときの形式。人間にも読みやすく、プログラムにも扱いやすいため。

### Q10. APIとは

このアプリではフロントエンドがバックエンドのAPIを呼び出してデータを取得しています。

- APIとは何ですか?
- なぜ直接データベースにアクセスしないのですか?

フロントとバックエンドをつなぐ窓口。勝手にデータにアクセスや操作されないように制限をかけるため。

### Q11. CORSとは

フロントエンド(5173)からバックエンド(8080)にアクセスする際、「CORS」という仕組みが関係します。CORSとは何のためにありますか?

CORSは、フロントエンドから別オリジンのバックエンドへアクセスするときの検問所のような役割。

### Q12. クライアントとサーバー

「クライアント」と「サーバー」とは何ですか?このアプリの構成の中で、それぞれどれがクライアントでどれがサーバーですか?

- ブラウザ: クライアント
- バックエンド: サーバー
- データベース: バックエンドから見たらサーバー

クライアントは依頼をする側、サーバーは依頼を受ける側。

## 第2章 Webアプリケーションの構造(8問)

### Q13. フロントエンドとバックエンド

「フロントエンド」と「バックエンド」の違いを説明してください。このアプリではそれぞれ何を担当していますか?

フロントはお客様に見える見た目、実装の部分を担当。バックエンドはその裏のシステムを作る役割。フロントがお客さまの求めるものをバックエンドに処理をお願いする役割、バックエンドは届いたものをDBに依頼してフロントに返信をする役割。

### Q14. 3層構造

このアプリは フロントエンド / バックエンド / データベース の3層構造です。なぜこのように役割を分けるのですか?1つのプログラムですべてをやらない理由を説明してください。

全部を1つにまとめると、1か所の変更や異常が他の部分にも影響してしまう。3つに分けることで、それぞれの役割を分担でき、問題が起きたときもその部分を中心に直せる。また、アクセスできる範囲も分けられるのでセキュリティなどの安全性も高められる。

### Q15. データの流れ

ユーザーが「新しいタスクを作成」ボタンを押してから、データベースに保存され画面に反映されるまでの流れを順を追って説明してください。

1. ボタンを押す
2. フロントがHTTP(POST)でタスク情報をバックエンドへ送る
3. バックエンドが受け取り、DBに保存するよう処理する
4. DBがタスクを保存する
5. バックエンドが結果を受け取る
6. バックエンドがJSONなどのレスポンスをフロントへ返す
7. フロントが受け取ったデータを使って画面に反映する

### Q16. エンドポイントとURL設計

このアプリには `/api/tasks` と `/api/tasks/{id}` というAPIがあります。このようなURL設計の考え方を説明してください。`{id}` の部分は何ですか?

タスクというグループの中の1個を探すためのID。

### Q17. 同期処理と非同期処理

「同期処理」と「非同期処理」の違いを、日常生活の例えで説明してください。なぜWeb通信では非同期処理が必要ですか?

同期処理: クリーニングが終わるまで店で待つ。非同期処理: クリーニングが終わるまで別のことをする。通信を待っている間、ユーザーが別の画面など別のことをできるようにするため。

### Q18. SPA(シングルページアプリケーション)

このアプリはReactで作られたSPAです。従来のWebサイト(ページ遷移するもの)と何が違いますか?

ページ全体を移動、読み込みではなく、同じページの必要な部分を変更する。部屋ごと変えるのではなく、部屋のレイアウトを変えるイメージ。

### Q19. 入力チェック(バリデーション)の多重防御

入力チェックはフロントエンドとバックエンドの両方で行うべきと言われています。なぜ片方だけでは不十分なのですか?

フロントは、バックエンドに情報を送るために間違いがないかをチェックするためのもの。バックエンドはきちんと内容があっているか確認が必要で、じゃないとDBに入れたあと、今後データを引っ張ってくるとき間違った情報が出てきたりするため。

### Q20. エラーハンドリング

API呼び出しが失敗した場合(ネットワーク障害やサーバーエラーなど)、アプリはどのように対処すべきですか?

フロント側がエラーを検知、受取、画面に表示する。

### Q21. データベースとは

データベースとは何ですか?ExcelやCSVで保存する方法と比べて何が優れていますか?

データを保存して、データを管理するもの。整理されているので、必要な時に必要な情報を取得できる。

### Q22. テーブル・行・列

以下をExcelのシートに例えて説明してください。tasksテーブルで具体例も挙げてください。

- テーブル = tasksの表全体
- レコード = 1件分
- 列 = 項目

### Q23. 主キー(PRIMARY KEY)

tasksテーブルの `id` は主キーです。

- 主キーとは何ですか?
- なぜ必要ですか?

データを1件ずつ区別するもの。ほしいデータを特定するためのもの。

### Q24. CRUD操作

CRUDとは何の略ですか?それぞれがこのアプリのどの機能に対応するか説明してください。

- Create: 新規登録
- Read: 取得、参照

tasksテーブルでは `NOT NULL` と `DEFAULT 'medium'` が設定されています。これらは何のためにありますか?

データに空欄や情報不足が起きないようにするため。

### Q26. インデックス

インデックスとは何ですか?本の索引に例えて説明してください。

探すための目印、目次。

### Q27. トランザクション

トランザクションとは何ですか?タスクを別カラムへドラッグ移動する操作で、なぜ重要ですか?

トランザクションとは、複数の処理をひとまとまりとして扱い、途中でエラーが起きた場合に、変更前の状態に戻せる仕組み。

### Q28. SQLとORM

- SQLとはどのようなものですか?
- ORMの役割とは何ですか?

SQL: DBに直接伝えるための言葉の役割。ORM: プログラムとDBの間を取り持ってくれる通訳。

## 第4章 開発プロセスとチーム開発(4問)

### Q29. バージョン管理(Git)

Gitなどのバージョン管理システムとは何ですか?なぜ必要ですか?使わないとどんな問題が起きますか?

コードの変更履歴を記録して変更する仕組み。チーム開発などで誰が何を変更したかの確認がわかる。また何かしらエラーが出たり削除になったとしても、最後に記録したところから始めることができる。セーブポイントからまた始められる。

### Q30. ブランチとPull Request

- ブランチとは何ですか?
- Pull Request の目的は何ですか?
- なぜ全員が main に直接変更しないのですか?

ブランチ: 別の場所でコードの変更、開発を行うためのもの。切り離された枝のイメージ。
Pull Request: 変更内容を他の人にレビューしてもらい、問題がないか確認してもらうためのもの。
なぜ全員がmainに直接変更しないのか: エラーコードなどを書いてしまうと、動作不良などにつながる可能性があるため。

### Q31. コミットメッセージの重要性

例: `feat: ログイン機能を追加`

良いコミットメッセージを書くことがなぜ重要ですか?

何をしたか具体的に残さないと、次の開発者が何を変更したのか分からず困るため。

### Q32. なぜ技術的な仕組みを理解すべきか

AI時代においてコードはAIが書けるようになりました。それでも ネットワーク / データベース / Webアプリケーションの仕組み を理解する必要がある理由を、あなたの考えで述べてください。

AIが発達したことにより、開発スピードは上がったが、確実に正確なものが出来上がるとは限らないため。また、人間しかできない判断の部分の理解不足や要件定義などが曖昧だとお客様の要望をかなえてあげられない。適切なものを作成できず、エラーやバグなどシステムを使う人すべての人に迷惑がかかるため。あくまでAIは道具であり、人間が判断、操作することで最善なものがつくれるようになるため。
